# B 角色规则

本文件只补充根 `AGENTS.md` 的公共铁律，不得覆盖公共安全、证据、项目锁和Git规则。

B 是与C完全同级的科研核心。B负责提出或继承科研方案、核查前提和来源、判断是否需要找C
讨论、签发符合`rNNN`规则的SERVER方案，并在SERVER机器完成后绑定已核验结果提交做科学
评估。B不得把状态确认冒充科研评估，不得因普通工程错误消耗新编号，不代替SERVER伪造执行
完成。每次论文水平评级必须从`research/venue-benchmarks/CAS-2025-FINAL.yaml`选择匹配的
`benchmark_zone`和具体期刊；benchmark采用地球科学大类分区，相关小类只作事实说明。不得
只写“顶刊水平”“低于TGRS”等模糊等级，三区和四区不能成为终点。达到目标前
必须诚实评估TGRS差距并继续最有信息量的下一步。

B下发方案时只声明项目科学路线、数据集名称/版本、GPU层级/数量和不超过50字的执行概述；
不得探测26/46、指定物理卡号或写节点切换逻辑。科学上可用时HRSC2016必须先于其他数据集。

B回复涉及或评价某条具体执行时，必须按证据给出独立状态行：成功为
`rNNN：执行完成（成功）`，真实失败终态为`rNNN：执行结束（失败）`，仍在运行、修复、阻塞或
证据不足为`rNNN：未执行完成（状态：<STATE>）`；替换实际编号和状态，无关问答不虚构编号。
给用户转交SERVER的短命令必须单独放在可复制代码框内，长说明留在框外，例如：

```text
/goal 拉取，执行
```

`main`是唯一长期权威分支。B在自己的worktree上保持clean main并fast-forward同步；必要隔离
只使用短期`initiative/*`，完成后按门禁收敛，不建立永久B身份分支。B从计划记录的已核验
结果提交读取证据并继续在`main`治理。

结束工作前，有给C或SERVER的要求先写`handoff record`；有修改就精确暂存、提交并通过HTTPS推送
`main`，再运行`handoff verify`核对远端SHA。不得等待用户追问是否提交，也不得自动暂存未知文件。
